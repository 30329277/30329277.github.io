Editing apps optimise for one clip. Batches are a different problem

A batch is not “the same job, repeated”. It is a queue with mixed inputs: some files are already H.264, some are HEVC from a phone, one is a container with a broken tail, three need to be joined, and all of them need to end up in the same folder with sensible names. Handing that to a timeline-based editor means doing the boring part — the file management — by hand, one dialog at a time.

🗂 The per-file dialog tax

Export a 20-clip folder from a typical editor and you confirm the same preset, the same bitrate and the same output folder twenty times. VidForge asks once, for the whole queue.

⏳ Re-encoding what never needed it

Half of a typical batch is already in the target format. VidForge checks the codec first and stream-copies those files — a 45-second clip lands in under a second, bit for bit identical.

🧊 Waiting on one core

One export at a time leaves the machine idle. The queue runs 1–8 workers in parallel with per-file progress, per-file status and one shared cancel.

What “rule-based” actually means

Every tab is a set of rules, not a wizard: which files, what to do with each one, where the result goes, and what to do when the input is not ideal. Nothing is decided silently — the log prints the decision it took for every single file.

Job The rule VidForge applies
Convert H.264 inside an MP4-compatible container → stream copy. HEVC or anything else → re-encode that file only. Audio that will not decode → retry video-only instead of failing the batch.
Compress Estimate bits per pixel from resolution and frame rate. If the file has less than ~10% headroom, skip it — re-encoding would only cost time and quality.
Merge Compare codec, resolution, frame rate (±0.01) and pixel format. Match → lossless concat. Mismatch → re-encode so the join still works.
Clip Extract each segment by stream copy, fall back to re-encode per segment, then concatenate — with a full re-encode only if the copy path fails outright.
Repair Rebuild the container index by stream copy. Re-encode only when the timestamps are beyond saving.
Split Equal parts by count; either a precise re-encode cut, or a fast keyframe copy into a per-video subfolder — never overwriting the source.

Key Features

Six tools, plus the queue machinery that makes them usable on a folder instead of a file.

⇄ Batch Convert to MP4

Add files or a whole folder, choose an output folder once, and convert the queue with smart copy / re-encode. HEVC phone footage becomes universally playable H.264 without touching the clips that were already fine.

🛠 Video Repair

Feed it the leftover of an interrupted download — .!qb, .part, .bc!, .xltd, .emule.td — and get a playable MP4 back. A 45-second clip is repaired in about a second, by stream copy.

🗜 High-Quality Compress

Quality-aware compression with a bit-per-pixel estimate, so clips that cannot shrink are skipped instead of damaged. Manual override for size, bitrate, CRF or NVENC CQ — and a batch summary at the end.

✂ Clip & Merge

Independent segment sets for many files at once, compact time entry (0101 = 00:01:01), drag to reorder, keyframe align, GPU fallback, and JSON import / export so a repeatable cut becomes a reusable preset.

⇉ Merge Videos

Join recordings into one file in the order you set, with repeat count, custom output name, mp4 / mkv / mov container, optional CPU HEVC, and all audio and subtitle streams kept when copying.

⧉ Split Video

Split by parts count with presets, an optional precise cut, and automatic <name>_split subfolders so a long recording can be carved into chapters without collisions.

⚡ Parallel workers

1 to 8 files at a time behind a single queue and a single progress bar. Per-file status (Queued / Converting / Done / Skipped) and one Cancel that stops the whole batch cleanly.

🧠 Smart mode

Copy when possible, re-encode only when needed, choose the codec that fits the target, and keep the original when a compression pass would gain nothing.

🔒 Offline & private

Bundled FFmpeg, no telemetry, no network calls, no account. Logs stay in %LOCALAPPDATA%. See the privacy policy.

How It Works

Four steps, and only the first two change per batch.

1
Add a folder, not a file Open the tab you need and drop in everything at once — Add Files for a hand-picked queue, Add Folder for a whole card. Every row gets a checkbox, a path and its own status.
2
Point at one output folder Type it once for the whole queue. Leave it empty and each result is written next to its source — split runs always create a per-video subfolder so nothing is overwritten.
3
Set the rules, then start Smart mode, parallel workers, compression quality, merge order, segment list. One click starts the queue with per-file progress and a live log.
4
Read the log, not a dialog Every file reports what happened: copied, re-encoded, skipped, repaired. Failures are isolated to that file — the rest of the batch keeps going.

Real‑World Use Cases

Where batch processing saves an afternoon, not a minute.

📱 Phone & action-cam footage

iPhones and recent Android flagships record HEVC. A folder of holiday clips becomes a folder of H.264 MP4s that play anywhere — TV, car head unit, an older editor — with the already-H.264 files passed through untouched.

🧲 Half-finished downloads

qBittorrent leaves .!qb, eMule leaves .part, browsers leave .crdownload siblings. If the video itself was mostly complete, that leftover is recoverable — the app rebuilds the index and you keep the footage.

🎥 Screen recordings & streams

OBS and capture tools produce 2–4 GB files that need cutting into chapters. Split by parts, or clip the interesting segments from a dozen recordings in one pass with a JSON preset.

🗄 Archive compression

Big MP4 libraries usually have 20–40% of wasted bitrate. The bpp estimate compresses what has headroom, skips what does not, and prints a total “saved 35%” summary so you know it was worth the electricity.

🎬 Multi-part recordings

Cameras that stop at 4 GB, or recordings split across sessions, merge back into one file without re-encoding when the parameters match — the quality of the original, one file out.

🏫 Course & meeting material

A term of lecture recordings: compress the heavy ones, merge the two-part sessions, split the three-hour ones per topic, and keep every output name predictable.

Frequently Asked Questions

Is VidForge free?

Yes. It is free on the Microsoft Store — no account, no subscription, no watermark and no upload quota.

Does it upload my videos anywhere?

No. All processing happens on a bundled FFmpeg build inside the app, on your machine. There is no telemetry and no network access at all — see the privacy policy.

Why is batch conversion so fast?

Because most of the work is skipped. Files already in an MP4-compatible stream are stream-copied — no decode, no encode, no quality change — and only the genuine conversions are re-encoded, in parallel. Nine mixed clips finished in about five seconds in the demo above.

Will it overwrite or modify my originals?

Never. Results are written to the output folder you choose; if you leave it empty, each result is written next to its source, and split runs always create a per-video subfolder. Your source files are only ever read.

Can it repair a half-downloaded video?

Usually, yes — as long as the downloaded bytes contain a readable stream. VidForge rebuilds the container index by stream copy, falling back to re-encode if the timestamps are beyond saving. It can only recover what was actually downloaded: a file that stopped at 30% will play for roughly 30% of its length.

Will merging re-encode and lose quality?

Only when the inputs disagree. VidForge compares codec, resolution, frame rate (with a ±0.01 tolerance) and pixel format; if they match, the files are concatenated as-is, so the output is bit-for-bit the same video. Mismatched inputs are re-encoded so the result still plays.

Do I need to install FFmpeg?

No. FFmpeg and ffprobe ship inside the app. Nothing is added to your PATH and nothing is downloaded at runtime.

Does it support HEVC / H.265 and NVENC?

Yes. In smart mode H.264 is copied and HEVC is re-encoded to H.264 for compatibility. Hardware NVENC is detected automatically for compression and fallback encodes, and CPU x265 is available as an option.

Can I run it on a laptop without a discrete GPU?

Yes. Hardware encoding is optional — the app falls back to libx264 / libx265. Stream copy and repair need no encoder at all, so they work at full speed on integrated graphics.

What are the system requirements?

Windows 10 or Windows 11, 64-bit. Around 200 MB of disk space for the app and its FFmpeg build. No GPU required; a discrete NVIDIA card simply makes compression faster.
